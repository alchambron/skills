# Automation contract

The coordinator operates on Alexis's Mac using the installed skills and his GitHub account. The orchestrator owns the event subscriptions, wakes, and private digest delivery. Use these contracts when configuring the routines.

## Wakes and dispatch

- **Arrival.** Subscribe to GitHub `pull_request` with action `review_requested`, repository `EnerZam/JouleMV`, and `requested_reviewer.login` equal to `alchambron`. Invoke `$review-queue` immediately with the PR number and run `plan --number N`. This reads the PR directly, including before GitHub search can index it. Acknowledge duplicate event deliveries through normal reservation checks.
- **Hourly.** Keep an hourly `$review-queue reconcile` wake around the clock. Run `digest --retry-pending` independently of GitHub, import successful exports, and record any remaining export errors. Run `plan` without a number. The sweep pages through all currently open PRs and selects direct requests that need work, including missed events, changed head or base, genuine re-requests after feedback, and failed or incomplete runs. Team requests and requests for another reviewer alone are held back. Also read durable active jobs, reconcile their real T3 thread state and advance parked runtime work FIFO when a slot becomes available. Schedule a queue wake on worker or slot completion so a parked job can proceed before the next sweep.
- **Availability.** Verify the Mac and relevant resources are available before asserting `--host-ready`. Already-reserved work in another slot can continue. On offline, busy, unknown or failed dispatch, persist the reason and retry on the next wake. If an actual update-from-work worker is contending for a checkout or resource this PR needs, inspect the real T3 thread and the resource owner. Schedule bounded retries (e.g. every 15 minutes for that wait) until it clears or the next 06:00 America/Toronto cutoff for the wait. Record the blocker at cutoff and leave the PR eligible for ordinary reconciliation. The queue reviews the current pins even when the updater did not run. A run record or clock time cannot establish active contention.
- **Serialization.** Use one dispatcher for selection-to-thread assignment across triggers (e.g. a nonblocking flock on `~/.codex/review-state/review-queue/dispatch.lock`). Reserve before starting the worker. Create the T3 thread idle first, or claim with a durable dispatch ID and save its thread/link mapping in the run directory. If dispatch is ambiguous, reconcile the mapping, thread, worker and artifacts before another launch. Keep an immutable one-PR selection and a unique durable run directory per attempt.

If runtime is queued, checkpoint in the same thread's ledger and yield. Resume the whole installed workflow from that checkpoint as soon as capacity permits. A request cleared by its own publication still permits report rendering, history, and owned cleanup. Further runtime starts or publications require a current direct request. Use review-all's publication readback and scenario reporting for any unfinished work. Record `publication.status: not_required` when a clean review requires no publication.

## Commands and shared state

Use the installed `review-queue/scripts/queue.py` with Python 3. Pass `--review-all PATH --respond-queue PATH` before the command for non-sibling installations. Production uses `~/.codex/review-state/review-queue`. `--state` is for isolated tests.

- `plan [--number N] --output FILE` reads GitHub and review-all history. At dispatch retain the selection metadata and exactly one unchanged entry in `selected`. Feed this file to review-all's collector. Claims recheck pins and reject selections superseded by a newer attempt.
- `claim --selection FILE --run-dir DIR --thread LINK --host-ready` returns a static reservation token. Before collecting or publishing, `guard --token TOKEN` rechecks the live request and both pins against the reservation. Continue only after checking the ledger matches those pins as well.
- `park --token TOKEN` moves from static to waiting for live after the static workers and their heavy operations have stopped. The PR stays reserved. `claim-live --token TOKEN --host-ready` rechecks GitHub and claims the shared runtime slot. Keep it through setup, acceptance and verified cleanup. Use `guard` again immediately before any publication.
- `defer [--number N] [--token TOKEN] --reason TEXT` records an external blocker for the digest. Claim and guard failures record their reason. If a guard reports moved pins or lost eligibility, stop affected work, reconcile publication and cleanup, report the saved result, and replan immediately if still eligible. Freshness also needs review-all's own final refresh.
- `finish --token TOKEN --status completed|blocked|failed [--reason TEXT] --cleanup-verified` saves a result and refreshes its local dated digest. Use `completed` only after review-all delivers the matching report with validated coverage and settled publication. The first completed finish checks the current GitHub head and base. If either moved, it saves a blocked result for the reviewed pins and the coordinator replans. If GitHub is unavailable, retry the completion check or record the reason as blocked. Use `blocked` or `failed` with the concrete reason for partial, interrupted or missing evidence. These outcomes can release a cleaned-up reservation offline even when the evidence is unreadable. Try to render the normal blocked report even when startup or testing fails. On interruption, recover the token from `state.json` or the digest, reconcile actual worker/runtime and publication status, and finish only after verified cleanup. No reservation expires.
- `digest [--date YYYY-MM-DD]` regenerates dated JSON and Markdown offline. Use Toronto dates. The default is today. `digest --retry-pending` re-exports dates whose results were committed before export succeeded. Import the returned `exports` paths even if other dates have `failures`. Failed dates stay pending for the next wake. Retrying `finish` with the same token also re-exports the date derived from the original `finished_at` without querying GitHub or changing the result.

Both queues use `~/.codex/review-state/queue-slots.lock` and account for active jobs in `review-queue/state.json` and `respond-queue/state.json`. The shared implementation lives in installed `respond-queue/scripts/shared_slots.py`. The total is **two static reviews or response analyses** and **one live runtime or response fixer**. Review-all's internal Standards and Spec axes stay intact. A parked review keeps ownership but consumes neither slot. Both queues use the same machine and state roots. Preserve the separate heavy-command lock at `$REVIEW_STATE_ROOT/heavy/slot-0.lock` (default `~/.codex/review-state/heavy/slot-0.lock`) with one slot for installs, builds, tests and runtime startup.

Before switching versions, pause wakes for both queues and reconcile active work and cleanup. Replace both complete skill folders with the compatible releases together and keep both state directories and review-all history. Legacy active reservations still count until verified cleanup and finish. Resume the updated routines only after old coordinators have exited.

## Digest delivery

The Mac writes `~/.codex/review-state/review-queue/digest/YYYY-MM-DD.json` and `.md`. On each finish and at the daily 09:00 America/Toronto wake, the orchestrator imports these into `/home/box/shared/t3-review-queue/digest/<date>.json` and `.md` on its host. Preserve the absolute original HTML path. If the digest reader cannot open Mac paths, stage the complete report and linked evidence directory in the private digest storage and link the accessible copy as well. The queue itself has no outbound messaging operation.

The JSON has `schema_version: 1`, `date`, `generated_at`, `repository`, `reviews`, `reservations`, and `skips`. Each finished review emits `token` (idempotent import key), `pr` (number), `head_sha`, `base_sha`, `verdict`, `outcome`, `html_path` (absolute path or null), `finished_at` (UTC ISO timestamp), `ping`, `reason`, `live`, `publication`, `thread` and `run_dir`. Preserve all attempts, active work and recorded reasons.

For the 09:00 digest, read the two Toronto calendar dates spanned by the interval since the previous 09:00 cutoff. Use `finished_at` and each skip's timestamp to select that interval. Deduplicate imported rows by token. Put one ping per PR at the top of the digest using its latest finish in the interval. Use `#1234 review ready, check before approving` for a completed report and the recorded blocked/failed text when applicable. Refresh current head and request status for display and label outdated results with the reviewed SHA. Keep report links, active or parked work, skips and cleanup below. Deliver this existing digest to Alexis only.
