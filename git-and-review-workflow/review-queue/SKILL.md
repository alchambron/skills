# JouleMV review queue

This is an orchestration layer over [review-all](../review-all/SKILL.md), not a new review policy. Explicit invocation to operate this queue authorizes review-all scoped to the eligible PRs, including its verified REQUEST_CHANGES publication rules and owned local acceptance. Creating, installing or editing this skill authorizes no reviews or schedules. Never APPROVE, merge, deploy, modify PR source, or contact people. Honor narrower instructions.

## Guard and inventory

Read review-all fully, its resolved companion instructions, references and script interfaces. Resolve its actual installed directory as `REVIEW_ALL`; pass it to every queue command. Run its `scripts/check_dependencies.py --check-updates` before each invocation/resumption. Stop on failure, using its installation instructions; report unknown latest-version status honestly. The queue helper additionally checks its own VERSION and requirements.json compatibility with review-all. Preserve `REVIEW_SKILLS_DIRS`, `REVIEW_STATE_ROOT` and the same `REVIEW_STATE_DIR` in every thread. Never use per-thread history roots to evade reuse or caps.

Authenticate as `alchambron`; stop otherwise. Only open non-draft EnerZam/JouleMV PRs with **alchambron currently directly requested** qualify, regardless of author. This is a reviewer guard, not an author-only queue. Recheck before dispatch, publication and runtime start; removed requests and closed PRs leave the executable queue, while their historical reports remain visible.

Run `python3 scripts/queue.py --review-all "$REVIEW_ALL" plan --output "$RUN_DIR/selection.json"` using the installed queue script's absolute path. This calls review-all's history selector and rechecks direct requests, excluding its unfinished-live exception for requests that cleared. It performs no GitHub writes and is the dry-run inventory. Partial inventory, offline/auth failures and unknown availability mean skip this invocation with evidence; preserve existing checkpoints.

## Arrival dispatch

Read [the scheduling contract](references/automation.md) before configuring or operating automation. Each newly arrived or changed request gets its own T3 top-level PR thread, as explicitly requested by this queue workflow. Record the returned thread link; reuse it for later stages. Do not launch a second thread for the same PR when one is already active. Limit scope to one PR by writing a selection JSON with the original metadata plus exactly that candidate in `selected`; call review-all's collector with that selection, then its ledger init/carry commands. Never invoke an unfiltered batch.

Before launching work, reserve a static slot with `queue.py --review-all "$REVIEW_ALL" claim --phase static --number N --run-dir DIR --thread LINK --host-ready`. For a new thread, create it idle/without dispatch first so its identity can be reserved; start work only after claim succeeds. If that host cannot create an idle thread, use a reserved unique dispatch identifier and save its mapping to the returned thread in the run directory. All coordinators share the default queue state directory. At most **two PR static reviews** run at once. A rejected claim means defer, not wait holding resources. Keep review-all's parallel Standards and Spec axes unchanged; the two-review cap counts PR review coordinators, not their internal axes. Enforce review-all's lower limits on heavy commands and child counts too.

Use review-all's unchanged static review, regression verification, manual-test-guide scenario planning, publication, readback and checkpoints. This invocation explicitly defers runtime execution until the overnight phase. Save unexecuted scenarios as blocked with `actual: deferred to overnight queue`; save live blocked with that reason. This is an incomplete acceptance checkpoint, never a successful run. Render its illustrated report and record history through review-all before releasing the static token with `finish --token TOKEN`. Static findings still follow review-all's publication rules; dependent and independent scenarios remain visible. No runtime starts on arrival.

Use the original history mode verbatim. Same-head completed evidence enters decision mode: carry and report **Your review decision is still requested**, without duplicate review or testing. Unchanged incomplete evidence resumes missing work; a re-request after issues follows discussion mode. Changed base, unavailable evidence and revision drift follow review-all's full/incremental/retry rules. A head-only skip must not conceal base drift, discussion or unfinished acceptance.

## Overnight acceptance

Only after the configured **22:00 America/Toronto update-from-work run has actually completed**, and before 09:00, process clean static checkpoints FIFO by static completion time. Read the predecessor receipt contract; clock time alone is insufficient. Refresh selection and ledger with review-all's resume; verify current direct request and both pins. A changed pin returns to static review before runtime setup.

Reserve `claim --phase live --number N --run-dir DIR --thread LINK --host-ready --update-receipt FILE`. Only one live reservation exists machine-wide across this queue. Hold it from before runtime setup through all scenarios and verified cleanup. Continue other eligible static reviews within the two-review cap. A live slot is additional to, not a replacement for, review-all's shared heavy slot: call/import its heavy_lock.py for installs/builds/start and its existing runtime/scenario helpers. Never copy their implementation. Check for unrelated runtimes/heavy work, memory pressure, host offline/unavailable or another updater before asserting `--host-ready`; unknown means skip. Queue reservations cannot police unrelated workflows: an unrelated runtime prevents queue runtime start even when no queue token exists.

Resume the same ledger and run review-all's complete acceptance, failed-scenario classification, readback-verified REQUEST_CHANGES, illustrated HTML generation and history recording unchanged. No source changes or user approval substitute for acceptance. Static-issue PRs retain deferred independent coverage visibly; this clean-static queue does not erase it. Before 09:00 stop admitting new runtime jobs; safely finish/clean current owned work or checkpoint and clean it if the digest deadline arrives. Never terminate another thread's resources.

Use finally-style cleanup and review-all's cleanup receipts. Release live tokens only using `finish --token TOKEN --cleanup-verified` after checking actual owned resources are absent. Crashed reservations never expire automatically: inspect their thread/run evidence, reconcile ambiguous publication, and verify cleanup before release. Missing ownership evidence keeps the slot blocked and appears in the digest. A dead process alone is insufficient proof that its database or servers are gone.

## Digest and delivery

At 09:00 generate `queue.py --review-all "$REVIEW_ALL" digest --output "$RUN_DIR/digest-index.json"`; this exports durable jobs, linked ledger/report paths and saved static/live/scenario outcomes, with missing evidence visible. The digest reader must read each linked results.json and generated report, refresh request/pin status, and distinguish current observations from historical evidence. Include PR/thread/report links, pins, static and live status, scenario failures and publication disposition, blockers, skipped host/predecessor runs, pending cleanup, and still-requested decisions. Use review-all's renderer for illustrated reports; inspect screenshots and follow its HTML delivery contract. No new report format or publication mechanism replaces it. Preserve evidence outside disposable worktrees and report all new readback-verified REQUEST_CHANGES separately. No acceptance pass implies approval or merge readiness.
