# Automatic review queue

Alexis authorizes operation of this queue on his GitHub account for open, non-draft PRs across repositories where `alchambron` is currently a directly requested reviewer and a local checkout is configured on this Mac. An authorized queue wake-up invokes the installed [review-all](../review-all/SKILL.md) with that one PR's scope, including its verified `REQUEST_CHANGES` publication and isolated local testing. Never approve, merge, deploy, edit PR source, clone repositories, or send outbound messages. Creating or installing this skill grants no new permissions and creates no routines.

Read [automation.md](references/automation.md) for trigger, checkout resolution, state migration, command, recovery, inline presentation, and digest contracts.

1. Resolve Alexis's installed `review-all` and `respond-queue` folders under `~/.codex/skills`. On each `review-all` invocation or resumption, read its installed `SKILL.md` and run its dependency and update check. Follow its resolved companions and honor their constraints. Keep the same `review-all` history and heavy-lock roots across threads.
2. On a review-request event, immediately plan that PR with `plan --repo OWNER/REPO --number N`. On hourly reconciliation, run `plan` without `--number` to search open, non-draft direct review requests across all repositories (`is:pr is:open draft:false user-review-requested:alchambron`) and check parked or interrupted jobs. Resolve each repository's local checkout from the configured checkout map or T3 project list. Surface the `ping` from any `needs_attention` plan row in the coordinator output. Dispatch only entries in `selected` and never clone from this skill. Key all queue state by `owner/repo#number` (legacy v1 JouleMV-only state migrates idempotently to v2 on read/write or via `migrate`). GitHub's current direct request and pinned base/head govern admission. A request for another reviewer or team alone gives no eligibility.
3. Never silently skip an eligible PR. Treat a PR as `awaiting Alexis decision at current pins` only when a finished review actually exists in the recorded ledger at that exact `(repository, number, head, base)` AND Alexis was already pinged for it in `review-queue`; otherwise select it. Record every skip with a concrete reason once in both the `plan` output and the dated digest so callers can surface it. On a same-head re-request (`kind: rerequested` / `discussion` mode), either publish a fresh review or escalate with `finish --ping-alexis --reason "..."` so Alexis receives an explicit decision ping; never resolve silently as `publication: reused`.
4. Claim a static slot immediately before dispatch into a durable, per-PR T3 thread using the repository-scoped run directory layout (`runs/<owner>/<repo>/pr-<number>-<head8>-<rand>/`). Keep the shared concurrency caps across all repositories and queues combined (**two static** slots and **one live** slot, enforced via `respond-queue/scripts/shared_slots.py` and `queue-slots.lock`). Run the actual installed `$review-all` scoped to the one PR in unattended/headless report mode and supply the queue's single-PR selection and resolved local checkout path. Follow all its stages, including independent Standards and Spec work, verified publication, scenario planning and real acceptance for clean PRs, cleanup, history, and generating `scenario-guide.html`, `inline-report.html`, and `summary.md` via `render_results.py` (skipping `html_preview`, `html_render`, and custom layout-check scripts). Check the reservation, current direct request, and both pins before starting work or invoking the publisher.
5. When static review verifies actionable defects and publishes a verified `REQUEST_CHANGES` review, skip scenario planning and live acceptance (record `live.status: not_required`) and finish immediately without claiming the live slot. When `review-all` is clean and needs acceptance, release the static slot (`park`) while retaining ownership of the PR, then claim the sole live slot (`claim-live`) as soon as host and shared capacity allow. Resume the same `review-all` ledger immediately. Guard again before runtime start and publication. Replan on revision drift. If GitHub clears the direct request after publication, preserve the verified feedback and finish cleanly after rendering and history. Reconcile the saved publication before any repeat.
6. Save the canonical `review-all` ledger, HTML reports (`scenario-guide.html`, `inline-report.html`), and inline Markdown summary (`summary.md`) outside disposable worktrees. With the worker stopped and owned runtime cleanup verified, run `finish` to emit the per-PR outcome, report paths, and ping into the local dated digest (`digest/YYYY-MM-DD.json` and `.md`). End the coordinator's T3 thread with the rendered Markdown review result inline (`queue.py summary --token TOKEN`, matching `respond-queue`'s structured table + detail presentation: verdict, findings with `file:line`, live scenarios run, GitHub review link(s), and HTML report link). Keep the HTML reports as well. The coordinator imports the dated digest into Alexis's existing 09:00 Toronto digest; no separate outbound message is sent.
