# Automation contract

This file documents triggers only. Installation creates no schedules, webhooks or coordinator jobs.

Wake on a submitted **human CHANGES_REQUESTED** review of an open PR authored by `alchambron` in `EnerZam/JouleMV`. Bot account types, `[bot]`, CodeRabbit and Copilot identities do not qualify. Discover and paginate live reviews and the complete connected open stack (ancestors and descendants); mixed ownership or incomplete API evidence fails closed. Only a reviewer's latest decisive review (approved, changes requested or dismissed) counts: a request later approved or dismissed no longer triggers. Stacks link only through head branches in `EnerZam/JouleMV`; fork heads, `work` and the default branch never link PRs, and a branch heading two open PRs is ambiguous and fails closed. Events carry no permission and do not replace checks before dispatch, every push, every reply and re-request.

## Commands and state

Use `python3 SKILL/scripts/queue.py [--respond-all PATH --respond PATH] COMMAND`.
The default shared Mac state directory is exactly `/Users/alchambron/.codex/review-state/respond-queue` (`~/.codex/review-state/respond-queue`). `--state` exists for isolated tests; production coordinators and children use the default, across all threads. Cross-machine reservations are outside this Mac's contract.

- `plan --output FILE`: calls respond-all's collector scoped to JouleMV and imports its history filter. Writes selection JSON compatible with `ledger.py queue`. Batch identity hashes all remaining feedback URL/date pairs; edited feedback changes identity. Every changes-requested item in a batch must still be its reviewer's current review. Repeated batches are listed as skips and must resume their saved run. Partial discovery fails closed.
- `claim --phase analysis|fix --number N --batch HASH --head SHA --run-dir RUN_DIR --thread ID --host-ready`: requires the run ledger's frozen batch to match HASH, rechecks live eligibility, current triggers and head, enforces two analyzer/one fixer caps and durable round limits, and returns a token. Analysis is allowed only on a new, queued or analyzed batch. A fix requires a finished analysis, settled CI or a prior `no_push`; no batch of the PR may be `waiting_ci`; after a push it requires saved `passed`/`failed` CI whose head equals the recorded pushed head and the claim head. Host readiness is the coordinator's current verified attestation; omit it for busy/offline/unknown status and the run is skipped. Claims never time out.
- `guard --token TOKEN --head SHA --snapshot FILE`: requires active fixer ownership, the frozen ledger batch, current batch triggers, open/author/stack/head, and live human feedback equal to FILE's original `humanFeedbackSnapshot` (respond's `feedback_snapshot.py`). Network checks run outside the state lock; the reservation is rechecked afterwards and any change fails. Run immediately before every push, reply and re-request. The publisher additionally checks its pinned head and snapshot. A guard is not a reusable permission receipt.
- `finish --token TOKEN --outcome FILE --cleanup-verified`: release after verified worker/runtime cleanup. Outcome fields: `status` (analysis: `analyzed`, `handoff`, `skipped`; fix: `waiting_ci`, `no_push`, `handoff`, `skipped`), optional `head`, `actions` (strings), `commits` (pushed SHA strings), `replies` (verified URL strings), `re_request` (reviewer-to-readback object), `ci` (`state`, `head`, timestamp/evidence), and `reason` (mandatory for handoff/skip). CI states: `pending`, `passed`, `failed`, `missing`, `unknown`, `not_required`. `waiting_ci` requires the pushed 40-hex `head`, listed in `commits`, and `ci` `{state:"pending", head}` on it. `no_push` requires no commits, an unchanged head and `ci.state` `not_required`. `finish` never completes a batch. Failed CI requires a next round or handoff, not completion.
- `observe-ci --number N --batch HASH --head SHA --ci FILE`: only for a `waiting_ci` batch with no live worker; SHA, FILE's `head`, the recorded pushed head and the pending CI head must match. FILE contains settled `state` (`passed`, `failed`, `missing`), `head` and evidence/timestamp. This command writes local evidence only; coordinator must obtain it from live exact-head checks. Use `handoff --number N --batch HASH --reason TEXT` for exhausted rounds, infrastructure or eligibility blockers with no live worker; terminal batches are never reopened.
- `complete --number N --batch HASH --run-dir RUN_DIR`: the only transition to `completed`. Requires `ci_settled` with `passed` CI on the recorded pushed head, or `no_push`; the respond ledger entry must match the batch, be settled (`history.settled`) and record the same head.
- `digest`: offline; atomically writes `digest-index.json` and a short `digest.md` (including active reservation tokens) in the state directory. Older state rows are normalized with defaults. Runs even when GitHub is unavailable. The external coordinator copies these to the 9 AM digest input; this skill neither schedules nor sends that digest.

## Durable digest schema (version 1)

Exact index path: `/Users/alchambron/.codex/review-state/respond-queue/digest-index.json`.
Markdown: `/Users/alchambron/.codex/review-state/respond-queue/digest.md`.

Top-level object: `schema_version:1`, `generated_at` (UTC ISO timestamp), `repository:"EnerZam/JouleMV"`, `source` (recorded-evidence caveat), `prs` (one object per PR/feedback batch), `reservations` (all job records), `skips` (latest 200 objects with reason and optional URL/head/command/timestamp; state retains the same bound).

Each `prs[]`: `number`, `feedback_batch` (SHA256 hex), `head`, `fix_rounds` (0..2), `status` (`queued`, `active`, `analyzed`, `waiting_ci`, `ci_settled`, `no_push`, `completed`, `handoff`, `skipped`), `actions` (array), `commits` (pushed SHAs), `replies` (verified links), `re_request` (reviewer-to-status/readback object), `ci` (state, exact head and observation evidence), `handoff_reason` (string or null), optional `updated_at`. A handed-off batch is terminal for automatic dispatch; retain its unfinished respond ledger and drafts. New feedback is a separate batch, but a live reservation on the PR blocks concurrent work.

Each `reservations[]`: `token`, `number`, `phase`, `head`, `batch_key`, `run_dir` (absolute respond-all run path), `thread`, `status`, `started_at`, optional `finished_at`. Active reservations remain visible after crashes. To recover a lost token, match number, phase, thread and run directory, verify the worker, checkout writer and runtimes stopped and journals reconciled, then `finish` with that token. The lock is `queue.lock`, durable state is `state.json`; neither is an acceptance result. Digest snapshots are recorded evidence, not current CI assertions.
